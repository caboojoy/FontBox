# 이미지 스타일 폰트 제작 (뭉툭마커 · 황야웨스턴)

참고 이미지의 글씨 느낌에 맞춰 **한글 11,172자 + 영문·숫자·기호를 모두 담은 TTF**를 만드는 프로젝트다.
글자를 하나씩 새로 그리지 않는다. 공개 라이선스(SIL OFL) 폰트를 래스터로 렌더링하고, 이미지 처리로 두께·질감을 바꾼 다음 다시 윤곽선으로 추출해 새 폰트를 조립한다.

## 결과물

| 폰트 | 파일 | 참고 이미지 | 베이스 폰트 | 스타일 |
|---|---|---|---|---|
| 뭉툭마커 (Mungtuk Marker) | `MungtukMarker-Regular.ttf` | 흑백 캐릭터 밈("겸손할 수 있을 줄 알았다") | Gamja Flower | 굵은 마커 손글씨, 둥근 획 끝, 약간의 손떨림 |
| 황야웨스턴 (Hwangya Western) | `HwangyaWestern-Regular.ttf` | 카우보이 일러스트 | 영문 Rye + 한글 Noto Serif CJK KR Black | 서부극 우드타입, 거친 잉크 외곽선, 닳은 자국 |

각 파일에는 글리프 약 11,380개가 들어 있다(한글 11,172 / ASCII 95 / 호환 자모 / 일부 기호).

## 파일 구성

```
build.py      # 폰트 빌드 스크립트 (스타일: marker | western)
preview.py    # 미리보기 PNG 렌더링
CLAUDE.md     # 이 문서
OFL-*.txt     # 베이스 폰트 라이선스 원문
*.ttf         # 베이스 폰트 (아래 '준비'에서 받는다. 저장소에 커밋하지 않아도 됨)
```

## 준비

```bash
pip install fonttools freetype-py opencv-python-headless scikit-image numpy pillow
# (리눅스 시스템 Python이면 --break-system-packages 추가)

# 베이스 폰트 (Google Fonts 저장소, OFL)
B=https://raw.githubusercontent.com/google/fonts/main/ofl
curl -sSfL -o GamjaFlower-Regular.ttf $B/gamjaflower/GamjaFlower-Regular.ttf
curl -sSfL -o Rye-Regular.ttf          $B/rye/Rye-Regular.ttf
curl -sSfL -o OFL-gamjaflower.txt      $B/gamjaflower/OFL.txt
curl -sSfL -o OFL-rye.txt              $B/rye/OFL.txt
```

**Noto Serif CJK (황야웨스턴 한글용)**
- 리눅스에 `fonts-noto-cjk-extra`가 설치되어 있으면 기본 경로(`/usr/share/fonts/opentype/noto/NotoSerifCJK-Black.ttc`, index 1 = KR)를 그대로 쓴다.
- 다른 환경(Windows/macOS)에서는 Noto Serif KR **Black** 굵기 파일을 받아서 환경변수로 경로를 지정한다. 파일은 notofonts/noto-cjk 저장소나 Google Fonts에서 받을 수 있다(정확한 다운로드 경로는 확인 필요).
  ```bash
  NOTO_SERIF=/path/to/NotoSerifKR-Black.otf python3 build.py western HwangyaWestern-Regular.ttf
  ```
  `.ttc`이면 index 1(KR), `.otf`/`.ttf`이면 index 0을 자동으로 쓴다.
- 가변(variable) 폰트 `NotoSerifKR[wght].ttf`는 기본 인스턴스(Regular)로만 렌더링되므로 쓰지 않는다. 반드시 Black 정적 파일을 쓴다.

## 빌드

```bash
# 1) 빠른 테스트: ASCII + 테스트 문구 약 120자, 몇 초 소요
QUICK=1 python3 build.py marker  test_m.ttf
QUICK=1 python3 build.py western test_w.ttf
python3 preview.py test_m.ttf test_w.ttf test.png

# 2) 전체 빌드: 2코어 기준 marker 약 2분, western 약 3.5분
python3 build.py marker  MungtukMarker-Regular.ttf
python3 build.py western HwangyaWestern-Regular.ttf
python3 preview.py MungtukMarker-Regular.ttf HwangyaWestern-Regular.ttf preview.png
```

파라미터를 바꿀 때는 **QUICK=1 → 미리보기 이미지 확인 → 전체 빌드** 순서를 지킨다. 전체 빌드는 시간이 오래 걸리므로 처음부터 돌리지 않는다.

## 파이프라인 (build.py)

1. `wanted()`: 대상 코드포인트를 정한다. ASCII(0x20–0x7E), 한글 음절(0xAC00–0xD7A3), 호환 자모(0x3131–0x318E), 자주 쓰는 기호.
2. `face_for()`: `SOURCES` 순서대로 해당 글자를 가진 베이스 폰트를 고른다. western은 Latin·구두점은 Rye, 나머지는 Noto에서 가져온다.
3. FreeType로 글자를 **240 px/em**으로 렌더링하고, 사방에 24px 여백을 둔다.
4. `process()`: 스타일별 이미지 처리를 한다. 아래 '조절 파라미터' 참고. 노이즈 시드는 코드포인트 기반이라 다시 빌드해도 결과가 같다.
5. `skimage.measure.find_contours`(임계값 0.5)로 윤곽선을 추출하고, `approximate_polygon`(tolerance 0.35)으로 점 수를 줄인다. 면적 150 미만인 티끌은 버린다.
6. `orient()`: 바깥 윤곽은 시계방향, 구멍은 반시계방향으로 맞춘다(TrueType 규칙, 포함 깊이의 홀짝으로 판정).
7. fontTools `FontBuilder`로 조립한다. UPM 1000, ascent 880 / descent -120, 실제 글리프 높이가 이 범위를 넘으면 win 메트릭을 넓힌다. name 테이블에 영문명과 한글명(0x412), 저작권, OFL 문구를 기록한다.

`multiprocessing.Pool`로 병렬 처리하므로 코어 수에 비례해 빨라진다.

## 조절 파라미터

### marker (뭉툭마커): `process()`의 marker 분기
| 항목 | 현재 값 | 효과 |
|---|---|---|
| 팽창 커널 `k = 2 * 4 + 1` | 반경 4px | 획 두께. 키우면 더 굵은 마커. 6이면 획이 뭉쳐 받침이 막히기 시작함 |
| `extra = 2 * U` (glyph_contours) | 2px | 팽창으로 커진 만큼 자간 보정. 커널을 바꾸면 같이 조정 |
| `GaussianBlur σ=2.2` | 2.2 | 획 끝 둥글기 |
| wobble `scale 40, ×1.6` | 1.6px | 손떨림 정도. 크게 하면 삐뚤빼뚤 |
| edge noise `×0.05` | 0.05 | 외곽 번짐 |

### western (황야웨스턴): `process()`의 else 분기
| 항목 | 현재 값 | 효과 |
|---|---|---|
| `GaussianBlur σ=0.9` | 0.9 | 잉크 퍼짐 |
| edge noise `scale3×0.13 + scale9×0.12` | 0.13 / 0.12 | 외곽선 거칠기(잔 요철 / 큰 굴곡) |
| pits `> 2.1` | 2.1 | 낮출수록 닳은 구멍이 많아짐. 1.8 이하면 작은 글씨에서 획이 끊김 |
| pits 감산 `- 0.9` | 0.9 | 구멍 깊이 |

공통: `approximate_polygon tolerance`를 키우면 파일 크기는 줄지만 윤곽이 각진다. 면적 필터 150을 낮추면 잔 티끌이 남는다.

## 새 스타일 추가하기

1. 참고 이미지와 가장 가까운 OFL 베이스 폰트를 고른다. 후보를 한 화면에 렌더링해 비교한다(Gaegu, Nanum Pen Script, Do Hyeon, Black Han Sans 등은 이미 비교해 봄).
2. `STYLE` 분기에 `SOURCES`, `FAMILY`(영문), `KFAMILY`(한글)를 추가한다.
3. `process()`에 새 분기를 추가한다. 출력은 0~1 실수 이미지이고, 0.5가 윤곽 기준선이다.
4. name 테이블의 `cpr`에 베이스 폰트 저작권을 추가한다.
5. QUICK 빌드 → 미리보기 → 전체 빌드 → 검증.

## 검증 체크리스트

```python
from fontTools.ttLib import TTFont
t = TTFont('MungtukMarker-Regular.ttf'); cm = t.getBestCmap()
assert sum(0xAC00 <= c <= 0xD7A3 for c in cm) == 11172
assert sum(0x20 <= c < 0x7F for c in cm) == 95
```
- 미리보기에 복잡한 글자(뷁, 쀍, 똠방각하)를 넣어 받침이 뭉개지지 않았는지 본다.
- 작은 크기(16–24px)에서 획 끊김이 없는지 확인한다.
- Windows에 설치해서 한글 이름(뭉툭마커/황야웨스턴)이 폰트 목록에 나오는지 확인한다.

## 라이선스 (반드시 지킬 것)

- 결과 폰트는 OFL 폰트를 변형한 것이므로 **SIL Open Font License 1.1**을 따른다.
- 이미지·영상·웹 등 상업적 디자인 작업에 사용할 수 있다. **폰트 파일 자체를 단독으로 판매하는 것은 금지**다.
- 배포할 때는 `LICENSE-OFL.txt`(원 저작권 표기 + OFL 전문)를 함께 넣는다.
- **예약 폰트명(Reserved Font Name)인 "Rye", "Source"는 파생 폰트 이름에 쓰지 않는다.** 새 스타일을 만들 때도 베이스 폰트 이름을 폰트명에 넣지 않는다.
- 상용 폰트, 라이선스가 불분명한 폰트, 이미지 속 실제 레터링을 베이스로 쓰지 않는다.

## 알려진 함정

- freetype-py는 가변 폰트를 기본 인스턴스로 렌더링한다. 굵기가 필요하면 정적 파일을 쓴다.
- Rye에는 한글이 없다. western에서 `SOURCES` 순서와 predicate(`c < 0x250` 등)가 Latin/한글 분기를 결정한다.
- 팽창(dilate)을 쓰는 스타일은 글리프 폭이 커지므로 advance 보정(`extra`)을 하지 않으면 자간이 붙는다.
- 윤곽 방향이 틀리면 일부 렌더러에서 구멍(ㅇ, ㅁ 안쪽)이 채워진다. `orient()`를 건드릴 때 반드시 ㅇ·ㅁ·ㅂ·ㅎ을 확인한다.
- 전체 빌드 결과 TTF는 6–14MB다. 웹폰트로 쓰려면 `pyftsubset`으로 필요한 글자만 추리거나 woff2로 변환한다.
